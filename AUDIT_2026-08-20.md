# Orange Catalogue Technical Audit — 20 August 2026

> **Scope.** This audit reviewed the tracked project structure, build/deployment configuration, direct dependencies, client route loading, active tRPC procedures, Supabase access patterns and live table/index metadata, POS import flow, media flow, authentication boundaries, tests, and operations documentation. The goal was to simplify and improve the repository without changing the catalogue, POS, media, Messenger, or Admin product contracts.

## Executive summary

The application has a sound product architecture: the public storefront is separated from the lazy-loaded Admin and product-detail routes, the POS parser is bounded and cohesive, Cloudinary bytes remain outside PostgreSQL, and the active Supabase catalogue/import tables have appropriate primary, unique, and lookup indexes. No P0 security, data-integrity, or database-index issue was found.

The first high-value cleanup tranche addressed three verified sources of unnecessary production cost and maintenance risk. The Vercel production build was embedding a 367 KB Manus editor/runtime script in every HTML response; pnpm was silently ignoring its patch and override configuration; and five direct dependencies plus one incompatible development plugin supported no remaining Orange behavior. These were corrected without altering public or Admin contracts.

## Findings and disposition

| Priority | Finding | Evidence and decision |
|---|---|---|
| P1 | The production HTML embedded the full Manus runtime/editor payload. | `vite-plugin-manus-runtime` injected an inline `manus-runtime` script into both development and production HTML. The plugin now runs only for `vite serve`; Vercel builds keep only React and Tailwind plugins. |
| P1 | pnpm configuration was ignored. | Current pnpm warned that the package-level `pnpm` configuration was no longer read, leaving the Wouter patch and Tailwind transitive override unreliable. The settings now live in `pnpm-workspace.yaml`, where `pnpm install --frozen-lockfile` completes without configuration warnings. |
| P2 | Generic UI scaffold retained unused direct dependencies. | The `Button` and `Card` wrappers served only the 404 route. The 404 now uses equivalent semantic native markup; the error boundary now uses a static class string. The unused wrappers, helper, shadcn metadata, and five direct dependencies were removed. |
| P2 | A JSX-location development plugin had an incompatible Vite peer range. | It was not required by Orange behavior and caused an avoidable install peer warning. It was removed. |
| P1 | The custom Vite development bridge did not evaluate the command-aware Vite configuration. | This dropped the client root during local development and made `/src/main.tsx` fail to resolve. The bridge now evaluates the configuration for `serve` mode; the unnecessary cache-busting source query and its direct `nanoid` dependency were also removed. A direct local probe returned the source entry with HTTP 200 and the simplified 404 page rendered at 390×844. |
| P2 | Human-facing operations guidance had stale project facts. | `OPERATIONS.md` now reflects the public repository, current migration discipline, Supabase-hosted logo fallback, unified Catalogue editor, unassigned-category behavior, and pull-request release flow. |
| P2, deferred | Legacy OAuth/MySQL framework infrastructure is still active in the client bootstrap and request context. | Although Orange Admin uses its dedicated password session, `client/src/main.tsx` still uses the legacy redirect/session fallback and the server context still authenticates legacy users. Removing it would be an authentication migration, not safe dependency cleanup, so it was not changed. |
| P2, deferred | `server/storeRouter.ts` remains a concentrated router. | Import, media, and Admin catalogue assembly are stable but colocated. A split should be undertaken only with dedicated contract tests and a separate review, because the audit found no measured runtime bottleneck requiring a risky refactor now. |
| P2, deferred | Global stylesheet size is high. | `client/src/index.css` contains accumulated responsive Admin and storefront rules. Blind deletion would risk visual regressions, so this audit does not remove CSS without a selector-usage map and desktop/mobile visual baseline. |
| Environment gap | The full local suite requires deployment-only credentials. | The same five files and nine tests fail before and after this tranche because the sandbox has no Supabase, Cloudinary, or secure session-key test environment. This is documented rather than hidden. |

## Database, import, media, and security review

The live Supabase database remains small and appropriately indexed for current catalogue scale. The largest reviewed table was `import_changes` at 1,482,752 bytes, followed by `variants` at 876,544 bytes and `imports` at 753,664 bytes. Catalogue access paths include unique `products.cleaned_code`, unique `products.slug`, unique `variants.pos_code`, and indexes for product/category, variant/product, variant/color, media/product, media/variant, import-change/import, import-change/product, and import-change/variant lookup. No migration or index change was justified.

The POS parser already enforces workbook, sheet, and row bounds; normalizes once; preserves immutable POS codes; previews before apply; and keeps missing rows non-destructive. The Cloudinary workflow signs uploads server-side, constrains registered media to `orange/products/`, and stores metadata rather than image bytes in Supabase. The audit preserved these business-critical workflows unchanged.

## Follow-up order

The next safe optimization should focus on the Admin workspace’s query enablement and payload scope, especially deferring import-history and full catalogue requests until their workspace is active. That work should be a separate pull request with request-count instrumentation and mobile interaction verification. Authentication/OAuth removal should remain separate until the owner explicitly chooses the replacement session strategy.
